Messy team messages in. Checked tracker updates out.

Without takes mixed, messy plastic and turns it into material people can use. This prototype does the same job for launch updates: a model drafts each one, code tests it against the dates that cannot move, and a person approves it before the tracker changes.

Built by Ashutosh Birla for the Founder's Office Associate case study on the 1 March 2027 go-live.

One run looked clean. Repeating it showed where it breaks.

I ran the same five Exhibit E messages through the workflow many times on four models, then scored every run on the calls that matter to the founder. The first prompt failed most of them almost every time. The fixes are below, and so are the runs after the fixes.

What I changed between the first prompt and the second

  • The first prompt asked for the "latest safe date" for the founder. The models gave exactly that: 3 or 4 January, the zero-slack date. It now asks for the tracker's own date and bans the last possible one, and a rule blocks any deadline later than the tracker's.
  • The model never saw the contract clauses or planned salaries, so it could not know which decisions mattered. Both are now in the context.
  • New rules: a Red update must name a founder action or a next step, unplanned work cannot be Green, and a decision cannot be due on the day of the task it feeds.

What the code checks

The model reads well. It does not reliably reason about deadlines or know when to escalate. These rules run on every update, after the model and before a person sees it.

CheckWhat it catchesResult
Real dateDates that do not exist, such as 31 FebruaryBlocks
Date is in the messageA date the model inferred or inventedBlocks
Relative and tentative datesKal, parso, shayad: the date is kept but must be confirmed with the senderPerson checks
Evidence quoteA quote that is not word for word in the messagePerson checks
Hard-date collisionJoining after 7 Feb, consent after 15 Feb, delivery after 15 Mar with the penalty in rupees, go-live after 1 MarForces Red
Roll-up rowsOne person's good news turning the whole hiring row GreenBlocks
Change or confirmationA "change" that repeats what the tracker already says, and the reversePerson checks
Dependency rippleA date that moves later: every task downstream is listedPerson checks
Founder deadlineNo deadline, a deadline inside 10–20 Jan, in the past, or later than the tracker's own dateBlocks
Decision before the taskA founder decision due on the day of the task it feedsPerson checks
Red needs an ownerA Red update with no founder action and no next stepBlocks
Unplanned workA new task marked Green, or with no dependency proposedBlocks or checks
Coverage, routing, confidenceA message with no update, a non-launch item with no owner, any low-confidence updateBlocks or checks
